# #53 모의투자 보유 종목과 수익률

- 이슈: https://github.com/sirloinbh/money-ledger/issues/53
- 브랜치: `feat/53-holdings-returns`

## 목적

모의투자 계좌가 가진 종목의 평가금액·손익과, 계좌 전체의 총자산·수익률을 보여 준다. 거래 내역과 수익률 추이 차트는 #54에서 한다.

## 계산 규칙

새로 정한 사용자 결정은 없다. #52 결정(원화 현금 하나, 저장된 최신 종가와 환율)을 그대로 따른다.

- 평가금액 = `round(보유 수량 × 저장된 최신 종가 × 최신 매매기준율)`. 국내 종목은 환율 1이다. 주문 금액과 같은 식이고 SQL `numeric`으로 계산한다.
- 종목 손익 = 평가금액 − 남은 매입원가(`mock_holdings.cost_krw`, 수수료 포함, 평균원가). 종목 수익률은 이 손익을 매입원가로 나눈다.
- 총자산 = 현금 잔고 + 모든 보유 종목의 평가금액.
- 계좌 손익 = 총자산 − 시작 금액. 계좌 수익률 = 계좌 손익 ÷ 시작 금액. 실현 손익·평가 손익·수수료가 모두 들어간다.
- 수익률은 % 단위로 소수 둘째 자리에서 반올림(0에서 먼 쪽)하고, 문자열로 보낸다.
- 거래 중단 종목(#97)은 마지막으로 저장된 종가로 평가하고 "거래 중단"으로 표시한다.
- 종가나 환율이 없는 보유 종목이 있으면 그 종목의 평가금액과 계좌 총자산·수익률을 비워 둔다(틀린 합계 대신 "-"). 주문은 종가·환율이 있어야만 체결되므로 보통은 생기지 않는다.

## 변경 내용

- `backend/src/mock-holdings.ts`: `GET /api/mock/accounts/:accountId/holdings`
  - `summary`: 시작 금액, 현금, 매입원가 합, 평가금액 합, 총자산, 손익, 수익률
  - `holdings`: 종목(활성 여부 포함), 수량, 종가·기준일·지연 여부, 환율·기준일, 매입원가, 평가금액, 손익, 수익률. 평가금액이 큰 순서다.
  - 계좌와 보유를 한 SQL 문으로 읽어, 주문이 그 사이에 커밋돼도 이 응답 안의 현금·보유·총자산은 같은 시점 값이다. 계좌 카드의 "현금 잔고"는 따로 불러오므로, 다른 탭에서 주문하는 순간에는 잠깐 다를 수 있다.

  - 종목마다 "주문" 버튼으로 그 자리에서 주문 폼(#52)을 연다. 거래 중단 종목(#97)은 검색에 나오지 않으므로, 보유분을 팔 수 있는 길이 이것이다. 전부 팔아 줄이 사라지면 "… 보유분을 모두 팔았습니다"를 보유 영역에 보여 준다.

## 제한·후속

- 원화 금액이 JSON 정수 범위(2^53)를 넘으면 보유 응답 전체가 500이다. 저장된 종가가 단위 오류로 크게 잘못된 경우에만 생길 수 있어 그대로 두었다.
- 손익이 −1원처럼 작으면 수익률은 소수 둘째 자리 반올림이라 0%로 보인다.
- 실제 시세 키로는 확인하지 않았다(#85).

## 리뷰 기록

### 1차 — 병합을 막는 결함 없음, 4건 반영

- 보유 종목의 주문 폼을 연 채 계좌를 초기화하면, 새 계좌에 없는 종목인데 "… 보유분을 모두 팔았습니다"가 보였다. 보유 영역을 계좌 ID로 다시 그리게(`key={account.id}`) 고쳤고, 초기화 뒤 안내가 나오지 않는 화면 테스트를 더했다(고치기 전에는 실패함을 확인).
- 주문 폼이 한 화면에 둘(보유 종목, 종목 상세) 있으면 화면 낭독기에서 이름이 같았다. 영역과 폼 이름을 "삼성전자 모의 주문"처럼 종목 이름으로 붙였다.
- 시세나 환율이 없을 때 합계를 비우는 경우를 DB 통합 테스트로 확인한다(USD 환율을 지우면 Apple 평가금액과 총자산·손익·수익률이 `null`, 매입원가 합은 그대로, 평가금액 없는 종목이 뒤로).
- 계좌 카드 현금과 보유 영역 총자산이 다른 요청이라 잠깐 다를 수 있다는 점을 위에 적었다.
- 그대로 둔 것: 평가금액이 정수 범위를 넘을 때 응답 전체가 500이 되는 점(위 제한 참고).

### 2차 — 1차 4건 해결 확인, 병합을 막는 결함 없음, 코드 변경 없음

- 사소한 것으로 남긴 점
  - 같은 종목을 보유 목록과 종목 상세에서 동시에 열면 두 주문 폼의 이름이 다시 같다. 드물고 위치로 구분된다.
  - 주문 영역 이름("삼성전자 모의 주문")과 보이는 제목("모의 주문")이 다르다. 영역에는 이름 일치 규칙이 적용되지 않는다.
